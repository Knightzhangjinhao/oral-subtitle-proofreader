# 口播字幕校对 Skill

## 核心定位

将中文口播录音转写稿整理成适合剪映、CapCut 等剪辑软件导入的字幕文本。

实际口播与原始脚本不一致时，必须以录音转写稿为准。原始脚本只用于辅助校对专有名词、明显识别错误和上下文，不得强行把字幕改回脚本。

## 输入材料

最少需要：

- 录音转写稿，或用户直接上传的录音文件

建议同时提供：

- 原始脚本
- 专有名词表，如人名、品牌名、产品名、课程名、行业术语

如果用户提供录音文件，应先将录音转成文字，再按本 Skill 校对字幕。如果没有录音或录音转写稿，应要求用户补充。如果只有原始脚本，应说明不能当作实际口播事实处理，但可以整理成口播字幕格式。

## 核心原则

- 录音转写稿是唯一事实依据。
- 原始脚本只作参考，不覆盖实际口播。
- 不补充录音中没有说过的内容。
- 不把口播改写成书面稿。
- 只修正明确错别字、明显识别错误和可确认的专有名词。
- 可以删除无意义重复和过多语气词，但要保留情绪、转折和强调。
- 无法确认的词使用 `【疑似：XXX】` 标记。

## 工作流程

### 第一步：检查输入

确认是否有录音转写稿、原始脚本和专有名词表。若同时有转写稿和脚本，先明确以转写稿为准。

### 第二步：建立事实底稿

只根据录音转写稿理解实际口播内容，识别明显识别错误、重复和不确定词。不要参考脚本改写句子。

### 第三步：参考脚本校对

用原始脚本和专有名词表修正低风险错误，例如人名、品牌名、产品名、地名、课程名、数字、日期、金额。与脚本不同但语义成立的实际口播表达必须保留。

### 第四步：清理口语冗余

删除明显卡顿、连续重复和不影响语气的“嗯、啊、呃”等。保留“但是、不过、其实、真的、特别”等体现转折、强调和口语风格的表达。

### 第五步：处理标点

最终字幕稿不要像文章一样保留完整标点。

- 字幕行尾一般不加句号或逗号。
- 同一条字幕内部可以保留逗号、顿号。
- 问句、反问和强情绪表达可以保留问号或感叹号。
- 不要在每条字幕结尾机械添加标点。

### 第六步：字幕断句

断句优先级：语义完整 > 阅读自然 > 字数控制。

- 每条字幕单独一行。
- 每条尽量 8 至 18 个汉字，但不要为了字数拆坏语义。
- 如果完整语义需要，可以适当超过 18 个字，甚至超过 24 个字。
- 不拆专有名词、固定词组、主谓结构、动宾结构和修饰关系。
- 不把一句完整判断切成碎片。

## 不可拆结构

以下结构优先保持在同一条字幕内：

- `不是 A，不是 B`
- `有 A，也有 B、C`
- `能 A，大家还 B`
- `不是靠 A，而是靠 B`
- `是靠 A、B、C 和 D 立住的`
- `说 A，不是 B，不是 C`
- 多个例子共同服务同一个论点

如果内部需要停顿，用逗号或顿号连接，不要强行换行。

## 断句示例

错误：

```text
这个方案不是临时决定
不是随便尝试
```

正确：

```text
这个方案不是临时决定，不是随便尝试
```

错误：

```text
不是靠一句宣传语
说出来的
```

正确：

```text
不是靠一句宣传语说出来的
```

错误：

```text
是靠内容、节奏、表达
和细节立住的
```

正确：

```text
是靠内容、节奏、表达和细节立住的
```

错误：

```text
这个产品有基础功能
也有进阶功能、协作功能
```

正确：

```text
这个产品有基础功能，也有进阶功能、协作功能
```

## 输出格式

用户可以选择输出 `TXT` 或 `SRT`。

- `TXT`：默认格式，输出纯文本分行字幕，适合复制到剪映、CapCut 或人工检查。
- `SRT`：输出带编号和时间轴的字幕文件内容，适合导入支持 SRT 的剪辑软件。

如果用户没有指定输出格式，默认使用 `TXT`。

如果用户要求 `SRT`，必须满足以下条件之一：

- 用户提供了带时间轴的转写稿。
- 用户提供了音频文件，并允许先生成带时间轴的转写结果。

如果没有时间轴信息，不要凭空生成精确 SRT 时间码，应改为输出 `TXT`，并在修改说明中说明原因。

### TXT 输出

必须严格输出三部分，标题固定为：

```text
第一部分：最终字幕稿

第二部分：疑似错误词汇

第三部分：修改说明
```

### 第一部分：最终字幕稿

要求：

- 每条字幕单独一行。
- 不加编号。
- 不加时间轴。
- 不加解释。
- 行尾一般不加句号或逗号。
- 只输出可直接复制进剪辑软件的字幕内容。

格式：

```text
第一部分：最终字幕稿

这里是一条字幕
这里是另一条字幕
同一句内部可以有逗号，但行尾不机械加标点
```

### SRT 输出

如果用户选择 `SRT` 且具备时间轴信息，第一部分输出标准 SRT 内容。

要求：

- 使用连续编号。
- 使用标准时间码格式：`00:00:00,000 --> 00:00:00,000`。
- 每条字幕内容仍需遵守本 Skill 的校对和断句规则。
- 第二部分和第三部分仍然保留，用于疑似词检查和修改说明。

格式：

```text
第一部分：最终字幕稿

1
00:00:00,000 --> 00:00:02,000
这里是一条字幕

2
00:00:02,000 --> 00:00:04,000
这里是另一条字幕
```

### 第二部分：疑似错误词汇

列出所有 `【疑似：XXX】`。

如果能判断可能原词，写：

```text
【疑似：XXX】，可能为：YYY
```

如果没有疑似词，输出：

```text
无
```

格式：

```text
第二部分：疑似错误词汇

无
```

### 第三部分：修改说明

简要说明做了哪些删除、修正和断句调整。说明是否存在转写稿与脚本不一致的情况。不要逐条解释字幕。

格式：

```text
第三部分：修改说明

以录音或录音转写稿为准，参考原始脚本修正了明确识别错误和专有名词。删除了少量无意义重复，并按语义完整优先调整字幕断句。
```

## 用户使用模板

```text
请用口播字幕校对 Skill 处理下面内容。

【输出格式】
TXT 或 SRT，不填则默认 TXT。

【录音转写稿】
粘贴实际录音转文字内容。也可以直接上传录音文件。

【原始脚本】
粘贴原始脚本，可选。

【专有名词表】
粘贴人名、品牌名、产品名、课程名、行业术语，可选。
```
